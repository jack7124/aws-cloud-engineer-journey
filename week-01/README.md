An important concept I learned within AWS is Identity and Access Management (IAM). A root AWS account, which is the "architect" of the entire account, has explicit permissions over the entire AWS system. An IAM user is constructed by the root user to be a "daily driver" that does not have access to the AWS account administator tools that the regular root user would have. While cloud does have physical protections, like on-sight security, network segmentation, firewall and software rules, etc, they are not responsible for the general security of customer inputs. This is a shared responsibility model, where users will create IAM rules, data, configurations, and the cloud provider will protect their infrastructure through the previous defense mechanisms. A great example would be the IAM I set up here, as AWS does not require this, but for the sake of my own data, it is a basic practice for customers to implement. AWS themselves will focus on the protection of their service availibity, safety at scale, network, and more as part of their responsibility.
